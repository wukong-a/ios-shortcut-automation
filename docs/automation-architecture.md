# 自动化架构 · Automation Architecture

手机不在线、没人操作时，服务端如何让手机动起来？

## 核心约束

服务器**不能**主动向 iOS 推送指令：

- 快捷指令只能被「触发」运行，不能远程唤醒
- 没有常驻后台进程，App 被系统挂起就没有执行能力
- 官方通道（推送、iCloud）不承载任意指令下发

所以必须找到一个**手机自己能感知、且不需要人点**的触发源。

## 解法：邮件唤醒（Mail Wake）

```
┌──────────┐   ① 入队    ┌──────────┐
│  服务端   │────────────>│  任务队列  │
│ (cron/AI) │             │  (HTTP)   │
└──────────┘             └──────────┘
      │                        │
      │ ② 发唤醒邮件            │ ⑤ 拉取任务
      v                        │
┌──────────┐                   │
│  邮箱服务  │                   │
└──────────┘                   │
      │ ③ 邮件自动化命中          │
      v                        │
┌──────────────────────────────────┐
│           手机                    │
│  运行快捷指令 ──────> 执行 ──> ④ 回传结果 │
└──────────────────────────────────┘
```

### 为什么用邮件，而不是别的

| 方案 | 能否无人触发 | 问题 |
|---|---|---|
| 定时任务（每小时） | ✅ | 延迟最高 60 分钟，且空跑耗电 |
| 推送通知 | ❌ | 需要人点通知才能触发 |
| 快捷指令 URL scheme | ❌ | 需要另一台设备或人操作 |
| iCloud 共享 | ❌ | 触发不可靠 |
| **收到邮件自动化** | ✅ | **零人工，触发快（秒级）** |
| 收到短信 / 特定 Wi-Fi | ✅ | 依赖运营商或位置，不稳定 |

邮件是唯一同时满足「服务端可控、手机可感知、无需人工」的通道。

### 唤醒邮件里放什么

**只放信号，不放指令。**

```
Subject: Shortcut Trigger
Body:    wake
```

任务内容全部在队列里，手机拉到才知道要干什么。这样做：

- 邮件被转发、截图、邮箱被别人看到 —— 不泄露任何任务内容
- 换任务逻辑不用改邮件模板
- 一封邮件可以触发一批任务

## 完整链路

### ① 入队

服务端把任务写进队列，带幂等键防重复：

```bash
curl -X POST https://your-domain/tasks \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "action": "clipboard.get",
        "params": {},
        "idempotencyKey": "clip-1730000000000",
        "ttlSeconds": 600
      }'
```

`idempotencyKey` 必填 —— 手机可能因重试多次拉取，没有幂等键会重复执行。

### ② 发唤醒邮件

```bash
python3 build/wake.py
```

配置见 `build/wake.py` 文件头。默认 20 秒超时，失败即报错不静默。

### ③ 手机端自动化（一次性配置）

1. 快捷指令 App → **自动化** → 新建
2. 触发条件：**电子邮件**
   - 发件人：你的服务端发信地址
   - 主题包含：`Shortcut Trigger`
3. **关闭「运行前询问」** ← 关键，否则会弹窗等人点
4. 动作：**运行快捷指令** → 你的任务拉取快捷指令

### ④ 拉取与执行

手机运行拉取快捷指令：

```
GET /outbox  （带手机令牌）
  ↓
有任务？ ── 无 ──> 结束
  │
 有
  ↓
按 action 分支派发到对应实现
  ↓
执行（读剪贴板 / 截图 / 调用其他快捷指令 ...）
  ↓
POST /receipt  回传结果
```

实测数据：从手机拉取到回执 **600 毫秒**；含邮件触发在内，全链路约 **55 秒**。

### ⑤ 回执落库

服务端收到回执后更新任务状态，调用方轮询或等待回调。

## 失败模式与对策

| 现象 | 根因 | 对策 |
|---|---|---|
| 任务一直 pending | 邮件没被识别 | 检查发件人白名单、主题关键词 |
| 手机拉到了但不执行 | 自动化开着「运行前询问」 | 关掉询问 |
| 重试多次都无回执 | 快捷指令内部需要人工交互 | **按能力分类，只派发无人值守项** |
| 一批任务全超时 | 混入了一个需交互的快捷指令，阻塞派发链 | 分批派发 + 分类护栏 |
| 同一任务执行多次 | 缺幂等键 | `idempotencyKey` 必填 |

**最重要的一条**：混合批次里只要有一个需要交互的快捷指令，整条链会挂起，
后续任务全部超时。分类不是建议，是护栏。

## 其他可选的唤醒通道

邮件之外，以下触发源也能做到无人值守，按环境选用：

| 通道 | 适用场景 | 备注 |
|---|---|---|
| 定时触发 | 周期性任务 | 延迟最大 1 小时 |
| 特定 Wi-Fi 连接 | 回家/到公司 | 依赖位置 |
| 蓝牙设备连接 | 上车场景 | 需配对 |
| App 打开时 | 半自动 | 仍需人打开 App |
| NFC 标签 | 物理触发 | 需贴标签 |

多通道可以叠加：邮件负责即时唤醒，定时负责兜底。

## 安全要点

- 唤醒邮件**只含信号**，任务内容在队列，靠令牌鉴权
- 手机令牌与发信授权码分开存放，不写进代码
- 队列任务设 `ttlSeconds`，过期自动作废，防止陈旧指令被延迟执行
- 生产建议：唤醒邮件发件地址单独一个，只用于触发，不接收人工邮件
